# 承認済みメモの暗号化・非保存の技術検証

## 対応Issue

- Issue #7
- 主担当：もえ
- 確認担当：じま・みほ
- 状態：検証成功・成果物整理中（レビュー前）

## 目的

本人が承認し、保存に同意した整理メモを暗号化して
PostgreSQLへ保存し、正しく復号できることを確認する。

会話全文・入力原文・未承認内容を
DB・Redis・ログへ残さない設計を確認する。

## 検証範囲

- 架空の承認済みメモの暗号化・復号
- PostgreSQLへの暗号文の保存と読み戻し
- 未承認・保存同意なしのデータが保存されないこと
- ログ・エラーレスポンスへの本文や鍵の混入確認
- Redisへ会話本文・メモ本文・鍵を保存しないこと

## 保存可否の方針

以下は今回の検証方針。
本実装の項目・型・保持期間はDB設計などで確定する。

| 情報 | PostgreSQL | Redis | ログ |
| --- | --- | --- | --- |
| 会話全文・入力原文 | 保存禁止 | 保存禁止 | 出力禁止 |
| 未承認の整理結果 | 保存禁止 | 保存禁止 | 出力禁止 |
| 承認済みでも保存同意のないメモ | 保存禁止 | 保存禁止 | 出力禁止 |
| 承認・保存同意済みメモの自由記述 | 暗号化して保存可 | 保存禁止 | 出力禁止 |
| 復号したメモの平文 | 保存禁止 | 保存禁止 | 出力禁止 |
| 暗号鍵 | 保存禁止 | 保存禁止 | 出力禁止 |
| メモID・所有者ID・作成日時 | 必要な項目のみ保存可 | 本検証では保存しない | 本検証では出力しない |
| 利用制限用のカウンター | 本検証では保存しない | 本文を含めず、期限付きで保存可 | 本検証では出力しない |
| 固定の処理名・成功失敗・エラーコード | 本検証では保存しない | 本検証では保存しない | 秘密情報を含まないもののみ出力可 |

平文は暗号化・復号に必要な間だけアプリのメモリで扱う。
メモリからの完全消去を保証するものではない。

## 検証環境・秘密情報

- 手元のDockerに検証専用のPostgreSQL・Redisを用意する。
- 本番環境・共有DBは操作しない。
- テストデータは架空データのみ使用する。
- 暗号鍵は実行時の環境変数から読み込む。
- 暗号鍵をコード・Dockerイメージ・Gitへ保存しない。
- AIエージェントは.env.example以外のenvファイルを読み書きしない。
- 外部AIサービスは呼び出さない。
- 外部AI提供者でのデータ保持については、本検証では確認しない。

## 採用候補ライブラリ・鍵管理方針

### 採用候補

Pythonのcryptographyライブラリが提供するFernetを暫定推奨する。

理由：
- 独自の暗号方式を作らずに、暗号化・復号と改ざん検出を利用できる。
- 今回の架空メモで、PostgreSQLへの保存・読み戻し・復号に成功した。
- 改ざんした暗号文や異なる鍵での復号を拒否できた。

注意点：
- Fernetの暗号文には、暗号化した時刻が平文で含まれる。
- 暗号化だけでは、認証・所有者確認・ログ漏えい対策を代替できない。
- 正式採用は、DB設計・運用要件と合わせてチームで判断する。

公式資料：
- https://cryptography.io/en/stable/fernet/

### 今回の鍵の扱い

- テストごとにFernet.generate_key()で検証用の鍵を生成する。
- アプリはMEMO_ENCRYPTION_KEY環境変数から鍵を読み込む。
- 鍵をコード、Git、DB、Redis、ログへ保存しない。
- 鍵が未設定・不正な場合は、保存処理を拒否する。
- 検証用の鍵は保存しないため、継続利用するデータの鍵管理には使用できない。
- PostgreSQLは一時領域を使用し、コンテナ停止後のデータ保持を目的としない。

### 本番で追加確認が必要な事項

| 項目 | 確認・決定すること |
| --- | --- |
| 鍵の保管 | Secret Manager等の採用、実行環境への安全な受け渡し方法 |
| アクセス権限 | 鍵を取得できるサービス・担当者を必要最小限にする |
| 環境の分離 | 開発・検証・本番で異なる鍵を使用する |
| 鍵の更新 | 鍵の識別方法、更新手順、既存データの再暗号化方法 |
| 古い鍵の廃止 | 再暗号化やバックアップの復元条件を確認してから廃止する |
| 漏えい時の対応 | 鍵の交換、影響調査、再暗号化、連絡手順 |
| 紛失・復旧 | 鍵を失うと復号できないことを踏まえ、安全な復旧手段を決める |
| バックアップ | 暗号化データと鍵を分離管理し、復元できることを確認する |
| ログ・監視 | 本文・鍵・リクエスト内容が監視基盤や例外記録へ流れない設定 |
| 本人確認 | 認証済みユーザーの所有権と、承認・保存同意をサーバー側で確認する |

鍵の更新にはMultiFernetが候補となるが、今回は実装・検証していない。
本番の鍵管理サービスの導入も本検証の対象外とする。

## 再現手順

### 前提

- Docker Desktopが起動していること。
- コマンドはリポジトリのルートで実行する。
- 本構成は架空データ専用。共有DB・本番DBへ接続しない。
- Firebase設定、秘密鍵ファイル、envファイルは不要。
- 暗号鍵はテスト中に生成され、環境変数経由でアプリへ渡される。
- 初回のビルド・起動には、イメージとパッケージのダウンロードが必要。

### 実行

```bash
docker compose -f technical-verification/encryption-non-persistence/compose.yaml up --build --abort-on-container-exit --exit-code-from tests
```

期待する結果：
- 15件のテストが成功する。
- testsコンテナが終了コード0で終了する。
- PostgreSQL・Redisが自動で停止する。

### データとログの扱い

- テストは専用テーブルverification_memosの行を削除してから実行する。
- PostgreSQLのデータ領域はtmpfsで、停止後には保持しない。
- RedisのRDB・AOFによる永続化は無効にしている。
- Dockerのコンテナログは、停止後も残る場合がある。
- 実データや本番の鍵を使って実行しない。

### 確認範囲

- FastAPIへのリクエストはhttpxのASGITransportから送信する。
- 暗号化処理とPostgreSQL・Redisは実物を使用する。
- 外部公開したHTTPサーバーや、本番の認証・認可は検証しない。
- Redisは非保存の確認用で、アプリからの書き込み処理は実装していない。
