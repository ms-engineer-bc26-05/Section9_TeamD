# 情報収集方法の技術検証

## 1. 目的

Snow Manの公式INFOページに掲載された最新情報を、Webアプリへ自動的に取り込める可能性があるか確認する。

次の2方式を同じ条件で試し、取得精度・実装難易度・規約や運用上の懸念を比較する。

- 公式サイトから直接取得する方法
- OpenAI APIのWeb検索機能を使う方法

## 2. 共通条件

| 項目 | 内容 |
|---|---|
| 対象アーティスト | Snow Man |
| 対象ページ | <https://mentrecording.jp/snowman/news/> |
| 対象件数 | 検証開始時点の最新5件 |
| 取得項目 | 公開日・タイトル・URL |
| 正解データ | ブラウザで目視確認した最新5件 |
| 対象範囲 | 一覧ページのみ。記事本文は対象外 |
| 実行回数 | 必要最小限。原則として各条件1回 |

ページ更新による結果のずれを避けるため、正解データには確認日時を記録する。

## 3. 分担と編集範囲

| 担当 | 作業内容 | 編集する場所 |
|---|---|---|
| めぐ | 共通準備・OpenAI API方式・最終比較 | `baseline/`、`openai-web-search/`、`comparison.md` |
| もえさん | 公式サイトから直接取得する方式 | `direct-site/` |

同じファイルの同時編集を避ける。共通ファイルを変更したい場合は、事前にチャットで声をかける。

## 4. 検証の順序

1. めぐがブラウザで最新5件を目視確認し、`baseline/latest-five.json`へ記録する。
2. もえさんが`direct-site/README.md`に沿って、公式サイトから直接取得する方法を確認する。
3. めぐが`openai-web-search/README.md`に沿って、OpenAI APIのWeb検索機能を確認する。
4. 各担当が取得結果またはエラーを、それぞれの`result.json`へ記録する。
5. めぐが`comparison.md`へ比較結果と現時点の結論をまとめる。

## 5. 完了条件

- 目視確認した最新5件が基準データとして保存されている。
- 2方式それぞれについて、成功・失敗または実行を見送った理由が記録されている。
- 公開日・タイトル・URLの一致数を比較できる。
- MVPで採用できそうか、追加調査が必要かを説明できる。

## 6. 注意事項

- APIキーは環境変数`OPENAI_API_KEY`で管理し、ファイルへ直接書かない。
- `.env`はGitHubへ登録しない。
- エラー結果やスクリーンショットにAPIキーが含まれていないことを確認する。
- 公式サイトへの同時リクエストは行わず、1リクエストずつ実行する。
- 短時間に繰り返しアクセスしない。
- 規約上の懸念が解消できない場合は、プログラムからの取得を実行せず、その理由を結果として残す。
