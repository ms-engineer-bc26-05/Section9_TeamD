# 公式サイトから直接取得する方法

担当：もえさん

## 目的

Snow Man公式INFOページの一覧から、最新5件の公開日・タイトル・URLを直接取得できるか確認する。

## 調査項目

- 公式APIが提供されているか
- RSSが提供されているか
- 利用規約・サイトポリシーに自動取得に関する記載があるか
- `robots.txt`に対象ページへのアクセスに関する記載があるか
- 一覧ページのHTMLに公開日・タイトル・URLが含まれているか
- JavaScriptによる追加表示が必要か

## 進め方

1. まずブラウザ上で上記の調査項目を確認する。
2. 判断できない点をメモする。
3. 公式APIまたはRSSが見つかった場合は、その提供条件に沿って取得方法を検討する。
4. 見つからなかった場合は、ブラウザで保存したHTMLをローカルで解析できるか確認する。
5. 下記の実行条件を満たす場合だけ、一覧ページへプログラムから1回リクエストする。
6. 最新5件の公開日・タイトル・URLを抽出する。
7. 実行結果または停止した理由を`result.json`へ記録する。

## 自分で進めてよい範囲

次の作業は、調査担当の判断で進めてよい。

- ブラウザ上で公式API・RSS・利用規約・サイトポリシー・`robots.txt`を確認する。
- ブラウザの開発者ツールなどを使い、一覧ページのHTML構造を確認する。
- ブラウザで保存したHTMLを、公式サイトへ追加アクセスせずローカルで解析する。
- 調査結果、判断できなかった点、エラーを`result.json`の`notes`または`errors`へ記録する。

ブラウザで保存したHTMLそのものはリポジトリへ登録せず、手元だけで使用する。

## プログラムから取得を実行する条件

次の条件をすべて満たす場合のみ、公開されている一覧ページへ1回だけリクエストする。

- 明確な禁止事項が確認されていない。
- ログインや認証を必要としない。
- CAPTCHAやアクセス制限の回避を必要としない。
- 個人情報や会員限定情報を対象にしない。
- 一覧ページ1ページだけを対象とする。
- 同時アクセスや繰り返しアクセスを行わない。

これは技術検証の実行条件であり、本番アプリでの継続利用できることや、サイト運営者から許諾を得たことを意味しない。本番採用前には、利用条件や必要な許諾を改めて確認する。

## 停止する条件

次のいずれかに該当する場合は、回避や再試行をせず停止し、その時点までの調査結果を記録する。

- 利用規約などで自動取得が禁止されている。
- 規約上、実行してよいか判断できない。
- `403 Forbidden`や`429 Too Many Requests`など、アクセス拒否を示す応答が返る。
- CAPTCHA、ログイン、アクセス制限などの回避が必要になる。
- 想定外のページへ追加アクセスする必要がある。

停止した場合も、理由を説明できれば有効な技術検証結果とする。

## Gitでの作業範囲

1. `main`を最新にする。
2. `spike/direct-site-verification`ブランチを作成する。
3. 原則として`direct-site/`内だけを編集する。
4. `fetch.py`へ検証コード、`result.json`へ結果を記録する。
5. APIキー、保存したHTML、個人情報をcommitしない。
6. 作業完了後はブランチをpushし、めぐへ検証結果とブランチのURLを共有する。

共通ファイルや別担当のフォルダを変更する必要が生じた場合は、そのファイルは変更せず、めぐへ相談事項として共有する。担当範囲内の調査と結果の記録は、そのまま進めてよい。

## 完了条件

次のいずれかを説明できれば完了とする。

- 最新5件の3項目を取得できた。
- 一部の項目だけ取得できた。
- 技術的な理由により取得できなかった。
- 規約上の懸念があり、プログラムによる取得を見送った。

## 注意事項

- 対象は一覧ページのみとし、個別記事本文にはアクセスしない。
- 同時リクエストは行わない。
- 短時間に繰り返し実行しない。
