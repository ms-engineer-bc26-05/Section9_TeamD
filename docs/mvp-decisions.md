## 2. MVPの相談完了条件

ユーザーがAIとの対話を通して、出来事・感情・本音・背景・望みを整理し、次の三つから気持ちの扱い方を自分で選び、整理結果を確認できた時点で1回の相談を完了とする。

- 伝える
- 今は保留する
- 伝えない

整理メモの保存は本人が選択する。保存は相談完了の必須条件とせず、選択後に別の「次の一歩」や行動計画の入力も求めない。

## 3. 決定事項

### No.1 相談テーマ

相手を主語にした責める表現を避け、次の5テーマと「その他」から最も近いものを一つ選ぶ。

| テーマ | 画面上の説明例 |
| --- | --- |
| 会話・連絡・愛情表現 | 連絡の頻度、会話のすれ違い、愛情の伝わり方など |
| 暮らし・家事・生活習慣 | 家事の分担、生活リズム、片付け方など |
| お金の感覚の違い | お金の使い方・貯め方、負担の考え方など |
| 気遣い・思いやりの伝わり方 | 言葉や態度、距離感、気持ちの受け取り方など |
| 将来・価値観・二人の関係 | 将来像、結婚、仕事、家族、関係のあり方など |
| その他 | 当てはまるものがない、まだよく分からない場合 |

テーマは悩みを診断・分類するためではなく、相談を始めやすくする入口として使う。

### No.2 AIの追加質問と要約確認

- 出来事を整理する追加質問は原則1〜2問、ユーザーが希望する場合は最大3問とする。
- 画面6-Aでは、AIの理解が合っているかを確認し、必要に応じて訂正できるようにする。
- 訂正・再確認は、情報を集める追加質問とは目的が異なるため、最大3問のカウントには含めない。
- ユーザーが訂正内容を入力し、AIが修正後の理解を提示してユーザーが再確認するまでを1回と数え、画面6-Aで行う訂正・再確認は、出来事を整理する工程全体で最大2回までとする。
- 上限に達した後も内容が合わない場合は、質問や再確認を増やさず、本人が要約を直接編集する。
- 訂正・再確認の「最大2回」はMVPの初期値とし、技術検証・画面試用で負担や応答を確認した結果、見直しが必要な場合は別途相談する。

具体的なボタン文言・表示位置はIssue #9で決定する。

### No.3 感情候補と選択方法

次の候補から、今の気持ちに最も近いものを一つ選ぶ。

1. 寂しい
2. 悲しい
3. 不安
4. 怒り・いら立ち
5. モヤモヤ・違和感
6. 傷ついた
7. 自分を責める気持ち（情けなさ・罪悪感）
8. その他・まだよく分からない

感情を診断・断定するための分類にはせず、「完全に一致しなくても大丈夫」と案内する。

### No.4 感情を具体化する入力

感情を選んだ後は、次のどちらかへ回答すれば次へ進める。

- 自分の言葉で入力する
- 「うまく言葉にできない」を選ぶ

文章入力そのものではなく、感情を具体化するステップへの回答を必須とする。

### No.5 利用前の注意と相談窓口

- 初回利用時は詳しい注意・確認画面を表示する。
- 2回目以降も、相談前に短い注意を表示する。
- 登録・ログイン画面にも「つらさが強いときの相談窓口」への導線を設ける。

具体的な文言・配置はIssue #9で決定する。

### No.6 扱い方を選んだ理由

「伝える・今は保留する・伝えない」のどの選択でも、理由の入力は任意とする。

### No.7 保存メモの再編集

保存後の整理メモは、MVPでは閲覧・削除のみとし、再編集はMVP後の拡張候補とする。

### No.8 無料・有料プラン

- 無料・有料の差は、相談回数と保存件数を候補とする。
- 無料枠は、利用価値を試せる範囲を確保し、狭くしすぎない。
- 具体的な価格・相談回数・保存件数は、Issue #6のStripe検証結果を確認した後に決定する。
- 後続のAPI・DB設計では、具体的な回数を固定値として埋め込まず、後から変更できる設定値として扱う。

Stripeはテストモードを使用し、テスト決済と結果のアプリ反映まで実装すれば、スクールMUST要件を満たすことを講師へ確認済みである。
